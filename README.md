# CAPI

CAPI is the control-plane API for the CapySploit / CAPI service. It exposes three router groups:

- `/` and `/health` for health/status checks
- `/api/*` for public and authenticated user-facing routes
- `/admin/*` for admin-only operations
- `/lookup/*` for external lookup helpers

This project is built as a Cloudflare Worker-style service and is designed to run behind a lightweight request router in `src/orchestrator.js`.

## Project structure

- `src/orchestrator.js` — top-level request router and dispatcher
- `src/api.js` — user/API endpoints
- `src/admin.js` — admin management endpoints
- `src/lookup.js` — lookup services (FiveM, Minecraft, IP/domain lookup)
- `src/response.js` — shared JSON response helpers
- `src/config.js` — default app settings, route text, and config constants
- `src/vault-db.js` — database access and user plan logic
- `src/helpers.js` — rate limiting, cache, auth attempts, etc.
- `payload.js` — method payload definitions
- `test/` — Node test suite for regression coverage

## Request routing

All requests flow through `handleRequest()` in `src/orchestrator.js`.

- `/` and `/health` return service health info
- `/api/...` goes to `apiHandler()`
- `/admin/...` goes to `adminHandler()`
- `/lookup/...` goes to `lookupHandler()`
- unknown routes fall back to `routeNotFound()`

The router also enforces:

- request size validation
- rate limiting on protected routes
- maintenance mode checks
- DB initialization bootstrap when required
- request logging/webhook dispatch

## Response format

The base JSON response format is generated by `jsonResponse()` in `src/response.js`.

A real response looks like this:

```json
{
  "error": true,
  "message": "invalid credentials",
  "hint": "4 attempts remaining before account lock.",
  "timestamp": "2026-08-29T16:13:55.223Z",
  "service": "CAPI",
  "version": "1.0.0",
  "ads": "This spot is open for sponsors — book it for $5/month and stand out."
}
```

Important behavior:

- `error` always comes first
- `message` comes second
- `hint` comes after `message` when present
- metadata fields are appended by the response helper after the payload fields:
  - `timestamp`
  - `service`
  - `version`
  - `ads`
- `attempts` and `limit` are intentionally not included in the final auth error payload

## Auth conventions

The API expects credentials as query params for auth-based routes, such as:

```text
?username=alice&password=secret123
```

Some routes also accept bot auth via a bearer token:

```text
Authorization: Bearer <BOT_API_KEY>
```

If a user or bot is allowed to act on behalf of a linked Discord account, that flow is handled by the `allowUserOrBotAuth()` helper in `src/api.js`.

## Local development

Install dependencies:

```bash
cd /var/www/CAPI
npm install
```

Run the test suite:

```bash
npm test
```

Start the dev worker:

```bash
npm run dev
```

## Notes

- The project uses the shared response helpers from `src/response.js` to keep JSON payloads consistent.
- Response ordering is intentionally standardized to reduce client parsing issues.
- The repo includes a live-style endpoint catalog in [API_ENDPOINTS.md](API_ENDPOINTS.md) so developers can validate payloads against real server behavior.
